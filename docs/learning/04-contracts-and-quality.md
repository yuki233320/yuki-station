# 04 · 合同、回执与质量

## 固定标准

任务开始前应明确文件范围、岗位工具授权和验收标准。冻结合同为这次执行形成稳定的输入和标准，返工不能通过删掉标准使结果变成通过。

## 证据链

一次交付至少可以区分：

1. 模型提出了修改。
2. 工具实际修改了哪些文件，内容指纹是什么。
3. 可信固定脚本是否执行，逐项断言是什么结果。
4. 审核者能看到什么文件和回执，引用了哪些具体行。
5. 宿主是否允许将候选合入项目版本。

模型说“测试通过”只是文本，不是测试回执。文件审查可以确认源代码中的某些结构，但缺少执行证据的运行行为应标为未验证。

## 原始失败复现

在项目选择可信检查器并指定必须失败的标准后，宿主可在第一个 Worker 模型调用和写入前运行检查。只有实际执行并复现所选失败，任务才继续。基线与原始输入、脚本和回执绑定；后续返工或订阅续办复核原证据，不在修好的文件上伪造失败。

## 分流与复核

具体产物错误交给 Worker 修复。仅证据不完整或审核结论不一致时，先核对原始证据并有界复审。执行未知、脚本出错或需要改变原授权时停止等待处理。后续每轮仍须满足原质量标准。
