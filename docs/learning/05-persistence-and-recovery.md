# 05 · 持久化与恢复

## 任务事实与事件事实

任务会话、执行尝试和派工意图由会话 SQLite 管理。Trigger 来源、接收事件、研判结果、订阅和外部操作有自己的 SQLite 权威。它们关联同一个稳定任务身份，但不同时拥有同一任务状态的写入权。

## 幂等与未知

幂等的意思是，对同一操作重复确认时不会重复产生新结果。例如重复接收同一个来源事件，只应保留一条；重复核对已发布的结果，不应额外创建 PR。

但是，如果外部服务收到了写入而本机没收到回复，执行结果是**未知**。此时需要依据稳定身份与远端事实核对，不能假设失败并盲目重发。持久队列本身并不保证外部系统“恰好执行一次”。

## 重启和订阅

服务重启会暂停需要显式恢复的来源，已经持久化的事件与订阅继续保留。任务被中断、取消或动作结果未知时，后续消息可以留在队列中等待处理。旧会话按当时的合同和证据版本解释，不自动补造新的步骤。
