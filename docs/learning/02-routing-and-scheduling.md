# 02 · 模块与队列调度

## 学习目标

区分“一个任务怎样拆分”与“多个任务怎样排队”，理解依赖、完成事件和资源容量。

## DAG 与任务完成

复杂任务可表示为有向无环图（DAG）。节点是模块，边表示下游依赖上游产物。例如 A 完成后才能运行 C，B 与 A 无依赖则可以并行。调度器应在 A 真正完成并保存结果后释放 C，而不是只看 A 是否开始。

雪站的 [`dag_scheduler.py`](../../lancer-local/dag_scheduler.py) 使用完成驱动的方式发现可执行节点。定向修复会重新处理失败模块及受影响的下游，同时保留未受影响模块的原结果。

## 任务级排队

多个用户任务之间还有一层排队。雪站使用按项目轮转与 FIFO 的队列，限制整体活跃任务与单项目活跃数。排队任务不为每个任务长期占用一个等待线程。冻结的项目版本发生冲突时，应重新规划而不是静默把旧合同套到新版本。

## 容量池

控制类调用和 Worker 长循环分别使用资源池。当前配置为 control 1、worker 2，总技术并发 3。独立池能让执行较长任务时仍保留一定控制能力，但容量限制并不是费用预算，也不能证明真实系统吞吐已经提高。
