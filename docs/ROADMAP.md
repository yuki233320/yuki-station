# 发展路线

路线图用于组织工作，不表示功能已经发布。每一阶段以对应代码与可复现验证为准。

## 近期：验证可靠交付

1. 在隔离合成项目上，固定任务输入、模型参数与机器验收标准，验证完整链路：事件接入、Worker、子任务、真实测试、独立复核、版本交付及后续反馈。
2. 区分运行失败、取消、未收拢线程、供应商用量缺失和质量未通过。保留原始回执，不把未知用量补零。
3. 对已经达标的相同任务，比较队列等待、执行时间、实际 Token 与完整交付结果。

## 执行与上下文

- 在保留源码、标准和证据的前提下减少重复上下文，量化不同角色输入。
- 设计可授权的项目运行环境、依赖管理、环境指纹和测试发现。
- 把 Worker 的执行能力与调度、质量判断分开，逐步扩展可靠的工具接口。

## 事件与分发

- 增加来源适配，支持团队实际使用的群聊、邮件或日历，在每个来源定义稳定的事件串身份。
- 评估轻模型语义 Router，衡量路线选择准确度、等候时间与调用成本。
- 在明确授权的独立仓库中验证真实 PR、评论与 CI 续办，覆盖中断与恢复。

## 桌面分发

- 验证连接恢复、不同用户数据隔离与另一台物理设备安装。
- 完善签名、公证和面向贡献者的构建流程。
- 根据实际维护能力决定跨平台桌面客户端的优先级。
