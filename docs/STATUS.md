# 当前状态与验证

本页描述 2026-11-09 发布的 **0.2.8（12）**。源码与测试持续演进时，应更新日期、版本、证据和限制，而不是把旧测试次数当作当前版本的证明。

## 已实现

| 功能 | 状态与边界 |
| --- | --- |
| 本机项目与岗位 | 支持项目资料、工作小组、角色记忆、上下文和回放。数据以各用户自己的本机目录为准。 |
| 任务路由与容量 | 明确单模块、低复杂度的合同可由规则直接分派；其他任务可使用 Coordinator。当前工作台控制池 1、Worker 池 2，总技术并发 3。 |
| Worker 工具 | 按项目与岗位授权文件读写和固定检查。模型不能自行登记宿主脚本。 |
| 子任务 | 可显式授权同型号执行子任务。父级须检查和接纳候选，之后重新测试。 |
| 验收 | 任务合同与标准冻结，真实宿主检查和模型独立复核进入质量关卡。失败按原因进入有限修复、同产物复审或停止。 |
| Trigger | 支持 GitHub 轮询、本机认证自定义事件与定时事件。观察、研判和自动接单需各自配置。 |
| 订阅直通 | 已启用 `auto + direct` 的来源可认领同串后续事件，在原项目和原会话中继续。 |
| GitHub 草稿 PR | 支持在明确授权并通过宿主质量关卡后创建草稿 PR；订阅反馈后的新交付可以更新同一 PR。 |
| 桌面版 | Apple Silicon、macOS 12+ 独立测试版带 Python 3.12.16。构建使用 ad-hoc 签名。 |

## 验证证据如何理解

- **1000 项 Python 回归、194 项界面与流程检查**在对应 0.2.8 候选上通过。本公开快照另运行 1000 项 Python（12 项可选 MCP 测试因依赖缺席而跳过），随后接入本机已有 MCP 测试依赖单独运行相关 14 项并通过；公开快照的 194 项界面与流程检查也通过。
- 本机隔离数据下，自然后台调度完成两轮文件修改、固定脚本检查、独立复核和交付。模型答复使用 fixture。
- 本机模拟 GitHub 完成首次 PR、后续评论和 CI 输入、原任务第二轮交付及同 PR 更新。模拟结果不等于真实 GitHub 用户场景已经成功。
- 219 文件源码归档通过空白启动与 HTTP 检查。桌面包在同一台 Apple Silicon Mac 的不同路径和隔离数据下通过 13 项检查；没有第二台物理 Mac 验收。
- 早期三个真实雪站源码需求的复测，2/3 完成交付。另有三个针对合成订单任务的真实工作流，均未完整交付。它们的任务与条件不同，不合并成一个成功率。
- 最新一次合成基线由宿主复现原始失败，子任务读取文件后 JSON 解析失败，未完成修改。6 次请求的原始回执共 27,729 输入和 1,477 输出 Token，金额未知。相关格式纠正已做本地回归，但仍需要新的真实模型验证。

本仓库不包含用户项目、模型密钥、私有会话或生产执行日志。详细实现和验证入口可从 [学习目录](../README.md#学习目录) 与代码测试查看。
