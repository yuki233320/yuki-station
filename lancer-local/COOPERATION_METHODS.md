# 单智能体与多智能体协作评估方法

核查日期：2026-10-31。目标是判断某类任务在给定资源约束下是否值得协作，而不是预设多模型必胜。本轮在现有评测器上独立实现两个算法，不引入新运行时依赖，不复制第三方库代码。

## 1. 预算约束下的配对收益评估

借鉴 [CooperBench 官方仓库](https://github.com/cooperbench/CooperBench) 对同一工作量设置 solo / coop 并使用相同测试验收的实验设计。仓库 [pyproject.toml](https://github.com/cooperbench/CooperBench/blob/main/pyproject.toml) 和 README 声明 MIT。本轮借鉴评估协议，不安装其 Docker、Redis 或代理框架，也不声称复现完整 CooperBench。

[等思考 token 预算研究](https://arxiv.org/abs/2604.02460v2) 支持控制资源预算、上下文和任务类型；其结论针对所测模型与多跳推理任务，不能外推成所有项目上 SAS 必胜。相同预算上限也不等于实际消耗相同，需同时披露上限和实耗。

雪站的评估约束：

- 两臂使用相同任务、输入、验收器、工具范围和预先声明的预算口径；保留模型、工作流、评分器指纹及执行顺序。预算计入规划、讨论、执行、审阅和重试。
- 严格区分单智能体 SAS、同一型号执行多个角色，以及多模型 MAS。同型号多角色仍可能是多智能体；缺少拓扑证据的历史记录不能改名为 SAS 对照。
- token 消耗不同于 FLOPs。不同模型的 tokenizer、隐藏推理和服务商记账方式可能不同；只有同口径且完整的回执才能做预算判断。未知用量、缺失价格和不一致币种不得记作零成本。
- 同一案例多次重复只估计该案例的不稳定性，不等于多个独立业务案例。少量配对仅报告描述性结果，不产生普遍优越性或统计显著性结论。

历史 v2 实现边界：受控实验默认使用同一模型配置。SAS 在一个上下文中调用一次；MAS 顺序调用规划者、两个完整候选作者与汇总者，供应商输出额度按 `1:2:2:3` 分配，总上限与 SAS 相同，无自动重试。它是一次产出的 SAS 基线，不代表允许自审或工具循环的最佳单智能体。岗位候选的额外诊断验收不回馈模型；其耗时从对照墙钟统计中扣除，同时保留原始历时。

**历史 v2 只实现相等的供应商输出额度上限及实际用量审计，并未实现等总推理 token、等总 token 或等账单预算。** 输入与隐藏推理语义不能从现有回执完全核实，因此 `strictBudgetMatched=false`，最终优越性判断保持证据不足。费用也没有实际账单回执，不以推测价格补齐。以下比率可描述实耗，但不能补足这一控制缺口。

报告同时列出验收成功率、固定验收项得分、墙钟时间、总用量及每成功任务成本：

```text
relative_compute_overhead = (MAS 用量 − SAS 用量) / SAS 用量
cost_per_success = 全部尝试成本 / 验收成功次数
```

相对计算增量不等于“纯协调成本”；其中可能包含不同模型单次执行成本与返工。没有成功任务时，每成功任务成本应标为不可定义，而非零；SAS 用量为零或未知时不计算比值。

EGT 可作为预先指定的业务门槛：比较质量相对增益和 λ 倍成本相对增量，另受预算、质量底线和计算增量阈值约束。λ 与阈值是业务选择，不是论文通用常数；不能事后调参让某臂获胜。基准质量为零、预算不可比或数据不足时，结论保持未知。满足门槛仅表示当前配对的描述性优势，不证明协作的因果效应。

## 2. 交接过程的词法差异与验收变化

参考 [GEMMAS 正式论文](https://aclanthology.org/2025.emnlp-industry.106/)。原文 IDS 对通信关系加权，使用 TF-IDF 和 all-MiniLM-L6-v2 语义向量的余弦相似度，各占 0.5：

```text
SS(i,j) = 0.5 × cosine(TFIDF_i, TFIDF_j) + 0.5 × cosine(embedding_i, embedding_j)
w(i,j) = max(S_ij, S_ji) + max(T_ij, T_ji)
IDS = Σ w(i,j) × (1 − SS(i,j)) / Σ w(i,j)
```

本次未查得 GEMMAS 官方实现仓库和代码许可证；公开论文不等于代码已开源。论文所述 2.1%、12.8%、80% 是多智能体拓扑之间的示例，不是 MAS 与 SAS 的比较结果。

雪站采用 **GEMMAS 启发的词法过程诊断**：只对记录中存在的交接边计算 `1 − cosine(TFIDF_i, TFIDF_j)`，不推断不存在的消息、不引入 embedding 服务，也不称为完整 IDS。TF-IDF 采用 [scikit-learn 官方定义](https://scikit-learn.org/stable/modules/generated/sklearn.feature_extraction.text.TfidfTransformer.html)：

```text
idf(term) = ln((1 + 文档总数) / (1 + 包含该词的文档数)) + 1
vector(term, document) = term_count × idf(term)，再做 L2 归一化
```

可核查的开源实现为 [scikit-learn text.py](https://github.com/scikit-learn/scikit-learn/blob/main/sklearn/feature_extraction/text.py)，许可证为 [BSD-3-Clause](https://github.com/scikit-learn/scikit-learn/blob/main/COPYING)。雪站用标准库实现上述公式；分词规则和评估范围须随结果保存，不声称与完整库或语义嵌入等价。

词法差异只描述文本表面变化：同义改写可能差异高，必要的接口确认可能差异低。高分不等于正确或创新，低分不等于浪费，不能按相似度阈值直接删除讨论。

用同一固定验收器分别检查岗位产物与最终产物，另列“新增通过、回退失败、仍通过、仍失败”的验收项及证据。它描述交接前后的可验证变化，不能排除额外计算、偶然波动或主模型重做造成的影响，不能称为该消息的因果贡献。岗位只负责子任务时必须明确比较范围，不能把未负责的完整交付要求解释为失职。

GEMMAS 原文 UPR 按路径中提取答案与真值的匹配比例判定必要路径，并非按文本相似度判冗余。雪站尚无适用于业务交接路径的有效贡献证据，故 UPR 保持 `unknown`；没有计算值不记作零冗余。

## 未采用的归因与指标

本次未核实“IEEE A2A 明确提出所给 COR 公式”的原始出处，也未核实用户所述 MASEV 协调熵公式的论文与官方代码。现有公开 [MASEval 仓库](https://github.com/maseval/MASEval) 是 MIT 许可的系统评估框架，不能与该 MASEV 熵公式混同。

协调熵需要先定义可观测行为类别和概率分布，角色遵循度还需要预先定义角色目标分布；当前不据此自造“熵越高越好”或“越低越好”的结论。缺陷检测的平衡准确率、召回与误报只适用于有正负真值标签的数据；普通代码验收不把测试通过率冒充平衡准确率。

历史结果保留原始评分及缺失项。新版诊断单独展示，不反向补造预算、回执、模型身份或因果证据，也不据少量分数自动修改模型岗位权重。

## 本次 v1 实验协议缺陷与修正原则

首轮订单对照 `70107f1f9873` 中，原题要求仅最终汇总模块写 `result.json`，其他岗位使用不同交接文件；规划者据此要求 worker1 输出 `handoff/worker1_candidate.json`，而实验验证器只允许 `result.json`，使 MAS 在首个候选阶段失败。这是实验协议的文件路径冲突，不能将它解释为 MAS 业务能力失败。

只读诊断将 worker1 原候选的相同内容在内存中按 `result.json` 交给既有验收器，15/15 项通过；这仅定位失败原因，不代表未执行的后续协作已通过。原始响应、用量和整臂失败状态保留，不重写为成功。

v2 修正原则是明确候选在隔离上下文中提交回复数据，候选作者与汇总者都遵守相同的固定交付路径，覆盖原题面向生产模块的文件所有权安排；业务输入与验收标准不变。EGT 参数在新实验创建时冻结，避免以后修改默认阈值而无声改变旧实验的观察结果。v1 不补造预注册参数，也不与修正后的协议混为同条件样本。

## 3. 岗位之间的交接可靠性与互补作用

岗位分析分为有向流程观测和受控交互实验。前者回答“甲交给乙以后是否正常交付”，后者回答“同时加入甲乙是否比各自加入产生额外收益”。两者不能共用一个功劳分。

### 有向交接与会话级 Wilson 区间

参考 [CooperBench 论文附录 G](https://arxiv.org/html/2601.13295v2)：协调问题应联系对话、产物和验收证据；仅见代码或运行错误不能直接判某个岗位沟通失职。原项目开源与许可链接见第 1 节。雪站据此定义本地观测口径，不声称这是 CooperBench 原有的岗位评分算法。

本阶段只分析真实业务会话中显式模块依赖的产物交接边，以及这些边上的定向澄清。不覆盖所有主模型派单、审查和讨论关系，未纳入的关系不代表合作能力为零，也不声称已经测得完整沟通拓扑或角色遵循度。

当前对岗位 `a → b` 复核冻结任务契约、保存的交接包、上游节点响应引用及文本产物哈希，再联合观察下游模块的首次质量关卡。此处关卡可能包含模型产物审阅和已有工具检查，不等同于独立的确定性测试。多个上游会共享同一个下游模块关卡，不能把通过重复归功于各上游。当前分析器未重新读取原始请求，也不能复核仅有 `binaryRef` 的二进制内容；这类缺证据情况保持未知。保存的交接包与产物一致不证明模型理解、采纳或因该交接改进。

同一运行的模块边只算一次；同一会话内、同一分组的多个交接合并为一个观测单位：所有已开始的相关交接可追溯且首次关卡通过，才记一次联合成功；其中已有明确失败则记未成功；否则缺证据或缺关卡记未知。最终关卡字段只表示最近一次已记录的关卡，正在进行的任务不能据此宣称最终成功。报告列出交接机会、会话数、已判定/未知数、首次与最近关卡、修复及定向澄清记录；未开始的下游在总体覆盖中列为未到达边，不记交接失败或交接机会。目前未统计独立任务数，也未判断未到达究竟属于排队、取消还是上游阻塞。

在明确可判定的会话中，令 `n` 为会话数、`k` 为联合成功数、`p=k/n`。95% Wilson 区间为：

```text
z = 1.959963984540054
denominator = 1 + z²/n
center = (p + z²/(2n)) / denominator
radius = z × sqrt(p(1-p)/n + z²/(4n²)) / denominator
interval = [center − radius, center + radius]
```

实现可核对 [statsmodels 的 proportion_confint](https://www.statsmodels.org/stable/generated/statsmodels.stats.proportion.proportion_confint.html)、[官方源码 Wilson 分支](https://github.com/statsmodels/statsmodels/blob/main/statsmodels/stats/proportion.py) 和 [BSD-3-Clause 许可](https://github.com/statsmodels/statsmodels/blob/main/LICENSE.txt)。公式可用标准库计算，无需安装该库。`n=0` 时点估计和区间均为空；3/3 成功的区间下界约为 43.9%，不能展示成已证实的“100%可靠”。

Wilson 是二项观测的近似区间，需要独立、可比的试验单位；不用于文本相似度、连续质量分或四臂差分。会话去重只是避免同一会话刷大样本量，并不自动保证独立：同一题多次续跑、共享历史和相同项目的强相关会话不能据此宣称跨任务置信度。当前分组使用岗位、逻辑模型 ID、工作类型及已保存规范指纹，尚未完全排除具体任务、验收标准与模型连接变化的混杂；外部岗位文件正文也未随该分析载入。这些会话区间以独立可比为工作假设，只作小样本诊断，不自动排名或调整路由。今后做跨任务推断时，还需冻结模型与验收配置并识别独立任务单位。

### 四臂二阶差分与完整 Shapley interaction

固定主模型及其他背景岗位 `S`，只改变目标岗位 `i`、`j` 是否参加。用同一任务与验收器分别得到四种配置的价值：`v(S)`、`v(S∪{i})`、`v(S∪{j})`、`v(S∪{i,j})`。局部互补量为：

```text
Δij(S) = v(S∪{i,j}) − v(S∪{i}) − v(S∪{j}) + v(S)
```

正值表示在这组背景与评分尺度下联合效果超过加和，负值表示次加和，零表示未观察到交互；饱和的通过率也可能产生负值，不能直接解释为互相拖累。四臂必须真实执行，不能把未测 `v(S)` 填零，也不能用两个岗位各自候选分数替代相应配置的最终交付分数。现存 SAS/MAS 两臂不足以计算该量。若仅遮蔽已生成消息再复跑汇总者，估计的是这些固定消息的条件作用，并非岗位完整参与的作用。

完整 Shapley interaction index（SII）还需对所有背景联盟加权：

```text
Iij = Σ[S⊆N\{i,j}] |S|! × (n−|S|−2)! / (n−1)! × Δij(S)
```

参考 [shapiq 官方源码 ExactComputer](https://shapiq.readthedocs.io/en/latest/_modules/shapiq/game_theory/exact.html)、[精确计算说明](https://shapiq.readthedocs.io/en/stable/auto_examples/exact_computation/index.html) 和 [MIT 许可](https://github.com/mmschlk/shapiq/blob/main/LICENSE)。单个四臂差分通常不是完整 SII；所有岗位联盟的精确计算通常需每个任务评估 `2^n` 种配置。SII 是对称的岗位组合量，不表达 `a → b` 方向；也不能将所有二阶 SII 直接加总为总收益。

四臂的任务、输入、固定验收器、工具、模型及岗位规范需一致，预算分配、缺席岗位替代办法、评分尺度、执行顺序策略和重试规则须事前冻结并保存实耗。恒定输出额度仍不能冒充等总推理或等费用。一次四臂结果只提供观察到的局部差分；因果解释还依赖可信干预、隔离、随机顺序、重复与适当的不确定性分析，Shapley 公式本身不提供因果证明。文本相似度和主模型自述都不能补出缺失反事实。

本阶段计算已有证据支持的岗位流程观测。四臂公式与上述试验协议是后续受控实验的标准，本阶段未实现四臂计算器、未运行四臂试验，也未接入付费调度；界面中的岗位协同增益明确标为未测。现有两臂与缺失反事实不能补算该值，不自动修改岗位能力权重或模型路由。


## 4. 完成交付优先的 v3 协议

按用户要求，新实验取消总额度及 1:2:2:3 岗位分配。每次调用不再覆盖 `StudioClient` 的输出参数，沿用协议现有的单次技术设置；技术输出边界仍可能造成截断，不能称为无限输出或保证完成。截断保留原文与失败，避免把部分代码当成果。

新记录固定 `budget.mode=provider_default`、`cap=null`、`enforcement=none`，EGT 成本阈值关闭。费用由用户核对账单；雪站保留 Token、调用数、历时及成功/失败结果用于描述，不据成本推测中断调用。费用未知仍不填零。旧协议和原始历史不改写，v3 与旧协议不混为同条件样本。

这是相同任务与验收器下的未控制预算观察，不满足等总计算量或等费用的因果比较条件。完成链路与证明协作净收益仍分别报告。供应商拒绝、余额不足和网络错误仍可能阻断执行，取消预算不等于已达到生产级可靠性。
